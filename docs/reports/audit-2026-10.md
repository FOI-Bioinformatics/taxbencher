# Code and Functionality Audit — October 2026

**Scope**: full read-through of the Nextflow workflow, local modules, Python helper scripts, configuration,
schemas, test fixtures and documentation of taxbencher v1.2.0, followed by end-to-end execution of all test
profiles with conda, targeted negative tests and a rerun of the nf-test suite.

**Headline**: the pipeline *ran* but did not *benchmark*. The profile conversion produced invalid CAMI
profiles (so every OPAL metric was meaningless), the comparative analysis never produced anything but
placeholders, and the pipeline-level tests passed while OPAL was never executed. All of this is fixed in this
change set; the sections below document what was found, what was changed, remaining gaps and a SWOT.

---

## 1. Findings

Severity: **Critical** = wrong scientific results or silent failure; **High** = pipeline unusable in realistic
settings; **Medium** = robustness/reproducibility; **Low** = quality/documentation.

| # | Severity | Component | Finding | Status |
|---|----------|-----------|---------|--------|
| F1 | Critical | `bin/taxpasta_to_bioboxes.py` | Abundances were normalised across **all ranks together** and direct read counts were never summed over descendants. A gold standard generated by this code listed Bacteria at 15 % and species at 10 % in total. OPAL's L1 norm, Bray-Curtis, UniFrac and Shannon metrics were therefore computed on nonsense. | Fixed: per-rank clade-cumulative abundances, each rank sums to <= 100 % |
| F2 | Critical | `bin/taxpasta_to_bioboxes.py` | MetaPhlAn values from taxpasta are already cumulative per clade; summing them again double counts. There was no notion of count semantics at all. | Fixed: `--abundance-mode direct|clade`, chosen from `classifier`; inconsistent mode is a hard error |
| F3 | Critical | `bin/taxpasta_to_bioboxes.py`, module | When ete3 was missing or a taxid was unknown every row was dropped and a **header-only** profile was written; the module's `-s` check passed and the run "succeeded". The committed pipeline snapshots show exactly this: three byte-identical empty profiles, `ete3: not installed`, and only 3 tasks executed. | Fixed: error unless `--allow-empty`; OPAL module rejects header-only predictions |
| F4 | Critical | `bin/taxpasta_to_bioboxes.py` | `kingdom` (e.g. Pseudomonadati) was remapped to `superkingdom`, so superkingdom summed to >100 % and never matched a gold standard. | Fixed: only `domain`→`superkingdom`, `subspecies`/`no rank` below species → `strain` |
| F5 | Critical | `OPAL_PER_SAMPLE`, workflow | OPAL silently skips profiles whose `@SampleID` differs from the gold standard. Nothing checked this; a typo in `sample_id` yielded an OPAL run with gold-standard-only results and a green pipeline. | Fixed: pre-flight check of all `sample_id`s against gold standard headers; module fails on "Skipping assessment" or missing labels in `results.tsv` |
| F6 | High | `bin/comparative_analysis.py` | Expected a *wide* metrics table; OPAL writes a *long* `tool/rank/metric/sample/value` table, so PCA always fell back to a placeholder. | Fixed: pivot, PCA over metric×rank features incl. gold standard reference |
| F7 | High | `bin/comparative_analysis.py`, module | Looked for profiles in `<opal_dir>/../taxpasta_to_bioboxes`, a directory that never exists inside a task; differential analysis was always a placeholder. Where it would have run, it emitted **fabricated p-values** (0.05 if diff > 5 %, else 0.1). | Fixed: module receives the sample's profiles; descriptive observed/expected/log2/TP-FP-FN table, no pseudo statistics |
| F8 | High | `main.nf` | Relative samplesheet paths were resolved against `projectDir` only (fails for any real samplesheet when the pipeline is pulled from GitHub); `s3://`/`https://` URIs were prefixed with `projectDir`; missing files failed late inside a task. | Fixed: URI/absolute/samplesheet-dir/launch-dir/project-dir resolution with an explicit error listing the tried paths |
| F9 | High | `PIPELINE_INITIALISATION` | `assets/schema_input.json` was never used (`splitCsv` only). Duplicate labels silently overwrote each other's outputs and confused OPAL's `-l` mapping; `taxonomy_db` was unvalidated. | Fixed: `samplesheetToList` with the schema, `uniqueEntries: [label]`, `taxonomy_db` enum, stricter patterns (no commas/pipes) |
| F10 | High | workflow | Format detection by extension only: raw DIAMOND/MEGAN6 `.txt` outputs (own test fixtures use `.txt`) were treated as taxpasta output and failed downstream. | Fixed: header-based detection (`taxonomy_id` + `count`) |
| F11 | High | `tests/default.nf.test`, snapshots | Pipeline tests asserted success and snapshotted only `taxpasta_to_bioboxes/`; `.nftignore` hid MultiQC; OPAL/comparative outputs were absent from the snapshot (they never ran) and nobody noticed. | Fixed: fixtures are valid, OPAL and comparative outputs are part of the snapshot, HTML/plots ignored |
| F12 | High | `bin/fix_gold_standard.py` | Renormalised **across** ranks, i.e. turned a valid gold standard into an invalid one; crashed on non-integer taxids; required 4/5 columns. | Rewritten: per-rank semantics, `--fill-higher-ranks`, `--renormalise`, `--taxdump`, sub-strain aggregation, lazy ete3 import |
| F13 | High | `bin/validate_bioboxes.py` | Flagged "percentages do not sum to 100 %" over all ranks (penalising correct files), rejected empty `TAXPATH` elements (allowed by CAMI), no multi-sample support. | Rewritten: per-rank sums, multi-sample blocks, `--sample-id` presence check, warnings vs errors |
| F14 | Medium | `TAXPASTA_TO_BIOBOXES` | ete3 downloaded the live NCBI taxonomy into `$HOME/.etetoolkit` inside every task: needs network and a writable home in containers, results change with the download date, snapshot tests are inherently non-deterministic. | Fixed: `--taxdump` → `ETE3_BUILD_TAXDB` builds one database shared by all tasks; reduced pinned taxonomy for tests |
| F15 | Medium | test data | Gold standards were generated from a classifier profile with the buggy converter (so they *were* the Kraken2 output, mis-normalised); `test_raw` evaluated E. coli/S. aureus profiles against a Francisella gold standard; the "metaphlan" fixtures were Kraken-style direct counts. | Fixed: truth tables → gold standards via `fix_gold_standard.py`; `gold_standard_raw.bioboxes`; genuine cumulative MetaPhlAn fixtures; `bin/regenerate_test_fixtures.sh` |
| F16 | Medium | `OPAL_PER_SAMPLE` | Label order from `groupTuple` was arrival-order dependent; no check that labels and files have equal length; `opal.log` discarded; stub output did not match real output names. | Fixed: labels sorted, length check, log kept in results, stub creates `results.tsv` |
| F17 | Medium | configs | `conf/test*.config` hard-coded `outdir` (nf-core expects it on the command line) and set `max_cpus/max_memory/max_time`, which are not declared in the schema. | Fixed |
| F18 | Medium | workflow | Whole OPAL result directories were fed to MultiQC (which has no OPAL module) — no benchmark result ever reached the report. | Fixed: MultiQC custom-content table from comparative analysis |
| F21 | High | containers | `TAXPASTA_TO_BIOBOXES` referenced a Wave image running Python 3.14 on which ete3 3.1.3 cannot be imported (`ModuleNotFoundError: cgi`), and `COMPARATIVE_ANALYSIS` referenced an expired temporary Wave build (`wave.seqera.io/wt/...`, "not found"). Docker and Singularity profiles were therefore broken for both modules; only conda worked. | Fixed: frozen Wave community images built from `environment.yml` (Python 3.11), `oras://` variants for Singularity |
| F19 | Low | citations | OPAL was cited with the AMBER paper; tool citations were disabled in the methods description. | Fixed |
| F20 | Low | documentation | `raw-inputs.md` documented a samplesheet with wrong columns (`sample,classifier,...`); several docs described the comparative analysis and OPAL "spider plot bug" inaccurately. | Fixed where found |

Issues F1–F5 mean that **no result produced by v1.2.0 should be trusted**; runs should be repeated with this
version.

## 2. End-to-end testing

Environment: conda (no container registry access in the audit sandbox), Nextflow 26.10.4, nf-schema 2.4.2,
taxpasta 0.7.0, cami-opal 1.0.13, ete3 3.1.3, MultiQC. All runs used the reduced, pinned taxonomy
(`assets/test_data/taxonomy/taxdump.tar.gz`), so they are reproducible offline.

| Scenario | Result |
|----------|--------|
| `-profile test` (3 taxpasta profiles) | success, 7 tasks: ETE3_BUILD_TAXDB, 3× TAXPASTA_TO_BIOBOXES, OPAL_PER_SAMPLE, COMPARATIVE_ANALYSIS, MULTIQC |
| `-profile test_raw` (Kraken2/Centrifuge/MetaPhlAn raw outputs) | success, 10 tasks incl. 3× TAXPASTA_STANDARDISE |
| `-profile test_realistic` (~50 taxa incl. strains) | success, 7 tasks; species-level Completeness 0.9, Purity 0.5 for all three profiles against the truth table |
| samplesheet `sample_id` without gold standard match | aborts before OPAL with an explicit message naming the missing and available sample IDs |
| duplicate `label` | rejected by nf-schema samplesheet validation |
| non-existent input file | aborts immediately listing the three locations that were tried |
| raw DIAMOND output with `.txt` extension | routed to TAXPASTA_STANDARDISE by header inspection, run succeeds |
| relative path next to the samplesheet (different launch dir) | resolved and run succeeds |
| Kraken-style direct counts declared as `metaphlan` | conversion fails with "per-rank abundances exceed 100 %" instead of producing garbage |

Converter unit checks: Kraken2 direct counts → every rank ≤ 100 % (superkingdom 99.9 %, species 70 %
with 30 % unresolved below species, as expected); MetaPhlAn cumulative values → every rank exactly 100 %
without double counting; taxpasta lineage columns → identical profile without ete3; unknown taxids are
reported with their abundance share.

nf-test: all local module tests (ETE3_BUILD_TAXDB, TAXPASTA_STANDARDISE, TAXPASTA_TO_BIOBOXES,
OPAL_PER_SAMPLE, COMPARATIVE_ANALYSIS) and the three pipeline tests were rerun with regenerated snapshots;
see the commit for the recorded results. The MetaPhlAn OPAL metrics that looked absurd in the first
end-to-end run (L1 error 30, negative Shannon) were traced to the mislabelled fixture (F15), which is how the
clade-consistency error (F2) was added.

`nf-core pipelines lint` (nf-core/tools 4.2.1 against the 3.5.1 template): 206 tests passed, 20 ignored,
18 warnings (newer versions of nf-core modules/subworkflows available, `meta.yml` include lists of the local
utils subworkflow), 6 failures — all template drift between tools 4.2.1 and template 3.5.1
(`.github/workflows/pr-comment.yml`, `docs/CONTRIBUTING.md` missing; `branch.yml`, `linting.yml`,
`.gitignore`, `.prettierignore` differ from the newer template) and unrelated to this change set. The schema
and configuration checks covering the new parameters passed.

Docker profile (after registry access became available): pulling the referenced images showed that the
ete3 image runs Python 3.14 (ete3 import fails) and the comparative-analysis image no longer exists (F21).
New frozen Wave community images were requested from the module `environment.yml` files and pinned in the
modules; see the follow-up commit for the Docker end-to-end result with them. The OPAL "spider plot" failure
reported in earlier documentation did **not** occur with valid profiles.

## 3. Gap analysis

| Area | Expected for a classifier benchmark | Current state after this change | Gap / recommendation |
|------|--------------------------------------|---------------------------------|----------------------|
| Correct CAMI profiles | per-rank cumulative abundances, CAMI TAXPATH | implemented and validated | — |
| Count semantics per profiler | explicit, documented | `direct`/`clade` modes; only MetaPhlAn is `clade` | verify semantics for any new taxpasta profiler (e.g. sourmash) before enabling |
| Taxonomy versioning | pinned, recorded | `--taxdump` + `ETE3_BUILD_TAXDB`; version visible in run parameters | record the taxdump checksum in `pipeline_info`; consider shipping taxdump via `nf-core/test-datasets` for CI |
| Gold standard QA | validated before use | sample ID pre-check; `validate_bioboxes.py --strict` available | run the validator as a pipeline step (`VALIDATE_GOLD_STANDARD`) and fail early on per-rank sums > 100 % |
| Multi-sample benchmarks | many samples, one gold standard file | supported (per-sample OPAL); comparative analysis per sample | **no cross-sample aggregation** (mean/median metric per classifier over samples, ranking). MultiQC table is the only cross-sample view |
| Statistical comparison | paired comparisons across samples, confidence intervals | descriptive only (by design: one profile per classifier per sample) | add a cross-sample module (paired Wilcoxon / bootstrap CIs over samples) once >1 sample is the norm |
| OPAL parameters | normalisation, filtering, rank range, time/memory | `--opal_normalize/--opal_filter/--opal_ranks` | runtime/memory of classifiers (`-t/-m`) not supported; would need extra samplesheet columns |
| GTDB support | GTDB-based profilers | only via taxpasta lineage columns; `taxonomy_db` enum enforces the choice | document a GTDB example; consider a GTDB taxdump builder |
| Containers | reproducible images | Wave images referenced; conda fallback | `TAXPASTA_TO_BIOBOXES`/`COMPARATIVE_ANALYSIS` rely on Wave URLs that cannot be verified offline; publish pinned images (e.g. GHCR) and record digests |
| CI | tests exercise OPAL | fixtures valid, snapshots include OPAL/comparative outputs | CI matrix still runs `docker` by default where Wave images are needed; conda job should be mandatory |
| Lint | nf-core lint clean | `nf-core pipelines lint` not run in this sandbox (tooling installed late) | run in CI (`linting.yml` already exists) |
| Reporting | one place to compare classifiers | MultiQC OPAL summary table per sample×classifier | add per-rank line plots to MultiQC (custom content `linegraph`) |
| Input flexibility | taxprofiler outputs | taxpasta TSV and raw outputs | taxpasta `merge` wide tables (several samples per file) are not split; document or support |
| Documentation | accurate | main docs updated | `docs/development/*` still contain v1.2-era descriptions in places (architecture diagrams, "placeholder" statements) and should be revised in a follow-up |

## 4. SWOT

**Strengths**
- Clear, narrow scope (evaluation only) on top of established standards: taxpasta for standardisation, CAMI
  profiling format, OPAL for metrics, nf-core template conventions.
- Per-sample grouping (`groupTuple` on `sample_id`) is the right unit of comparison and now has deterministic
  label ordering and validation.
- Good error-message hygiene in modules; negative tests exist for every local module.
- After this change: reproducible, offline-testable taxonomy handling and fixtures derived from explicit truth tables.

**Weaknesses**
- Core scientific logic lives in standalone Python scripts without unit tests; the conversion bug survived an
  earlier "comprehensive audit" because tests only checked that files existed.
- Two modules depend on Seqera Wave image URLs that cannot be rebuilt or verified from the repository.
- No cross-sample aggregation or statistics; MultiQC content is minimal.
- OPAL 1.0.13 is old, single-threaded and fragile on degenerate inputs; it is also the only metric engine.
- Developer documentation is extensive but was partly describing intended rather than actual behaviour.

**Opportunities**
- taxpasta lineage columns make an ete3-free path possible (and the only GTDB path); pushing lineage
  generation into `TAXPASTA_STANDARDISE` (`--taxonomy <dir>`) would remove the ete3 dependency entirely.
- Truth tables + `fix_gold_standard.py --fill-higher-ranks` give a simple way to benchmark on simulated data
  (e.g. CAMISIM, in-house spike-ins) where only species/strain truth exists.
- The MultiQC custom-content hook can grow into a proper cross-sample dashboard without new dependencies.
- nf-core/taxprofiler integration: a samplesheet generator from taxprofiler's output directory would remove
  most user error.

**Threats**
- NCBI taxonomy churn (`superkingdom` → `domain`, new `kingdom` ranks in 2025) changes rank names and
  lineages; pinning via `--taxdump` mitigates but rank alias tables need maintenance.
- taxpasta may change count semantics for a profiler between versions (the `clade`/`direct` split depends on
  it); pin taxpasta and re-check `assets/test_data` behaviour on upgrades.
- nf-schema 2.4.2 with Nextflow 26 prints parameter listings instead of the detailed samplesheet error in the
  console (the run still fails); upgrade nf-schema when moving the minimum Nextflow version.
- Wave/quay availability: environments without registry access cannot run the container profiles.

---

## 5. Recommendations (prioritised)

1. **Re-run any benchmark produced with v1.2.0 or earlier**; the metrics were computed on invalid profiles.
2. Add a `VALIDATE_GOLD_STANDARD` step (reuse `validate_bioboxes.py --strict --sample-id ...`) so that
   malformed truth fails before OPAL.
3. Add a cross-sample summary module (mean/median per metric and classifier, rank-based scores) and feed it to MultiQC.
4. Replace Wave URLs with images built from the module `environment.yml` files in CI and pin digests.
5. Add Python unit tests (pytest) for `taxpasta_to_bioboxes.py`, `fix_gold_standard.py` and
   `validate_bioboxes.py`; they are the scientific core and are cheap to test without Nextflow.
6. Run `nf-core pipelines lint` and the conda nf-test matrix in CI on every PR; make the pipeline-level
   snapshot include OPAL `results.tsv` (done here) so a silent skip of OPAL can never pass again.
7. Revise `docs/development/*` to match the current implementation.
